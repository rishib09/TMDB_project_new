Reading notes

  • Two LLM calls per routed turn, up to three with a re-route. Router at route_node, synthesizer at synthesize_node. The funnel calls the same router again as an extractor and discards its intent. Both use ~google/gemini-flash-latest. The router is built without a reasoning parameter, so the alias's thinking spends the 1024-token cap before JSON is emitted (issue 79).
  • Filters never reach ChromaDB. On the hybrid path, year and genre constraints are post-filters over a 50-candidate pool, so "recent feel-good date-night" can shrink to under five hits while the corpus holds hundreds. Only SQL-path intents filter the full table.
  • Constraint state lives in two places with different lifetimes. Per-turn decision.filters is LLM-owned. Cross-turn session_preferences is mostly regex-owned. The merge points are retrieve_node (genres), funnel_node (years), and the router (exclusions). Each missing merge is one open bug: 78 years, 80 shown ids, 56 era on entry and impossible ranges.
  • Every gate was added to fix a misroute by the old 3B model (issues 23, 26, 27, 42, 53, 56). The router was upgraded to Flash in issue 29. The gates remain and now override the stronger model.
  • The eval dataset is single-turn. 35 rows, one query each, with expected intent and relevant ids. No row exercises funnel state, exclusions, or coreference across turns. The multi-turn defects are covered only by live walkthrough tests.
